# Архитектурные правила SoViCut

## Принцип изоляции
Изменение в одной области НЕ должно влиять на другую область без явной связи.

## Правила

### 1. Модульность
- UI-компоненты не содержат бизнес-логику
- Экспортные стратегии не знают о виджетах
- Связь только через явные интерфейсы (коллбэки, провайдеры)

### 2. Независимость функций
- Добавление UI-элемента НЕ должно ломать экспорт
- Изменение формата экспорта НЕ должно влиять на импорт
- Если два модуля связаны — это должно быть задокументировано

### 3. Единая ответственность
- `HomeScreen` — оркестратор, не содержит бизнес-логику экспорта
- `FilterGraphStrategy` — только сборка ffmpeg команды
- `AudioTab` — только UI для аудио-настроек
- Если функция выросла больше 50 строк — рефакторинг

### 4. Чистые входы/выходы
- Видео со звуком → экспорт со звуком (по умолчанию)
- Кодек, битрейт, разрешение — сохраняются по умолчанию
- Пользователь явно меняет только то, что хочет изменить

### 5. Обработка ошибок
- Каждый модуль обрабатывает свои ошибки
- Ошибка в UI не крашит ffmpeg процесс
- Логируй ошибки с контекстом
- Все команды ffmpeg должны логироваться перед запуском

### 6. Регрессионная защита
- Каждый исправленный баг заносится в `references/fixed-bugs.md` с grep-шаблоном
- Перед любым изменением — проверь `references/fixed-bugs.md`
- Перед коммитом — прогнать grep-проверки по всем fixed-bugs

### 7. Наименование
- Верхняя панель — `Toolbar` (лого, режимы, файл, экспорт)
- Нижняя панель — `TimelineControls` или `SeekBar` (шаги, нарезка, навигация)
- Избегать дублирования имён между разными компонентами
